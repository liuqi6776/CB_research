# Study 007 截面多因子研究 — 审计报告

审计对象：test_factor_validity.py、run_v3.py、run_v3b_smallcap.py（附带核查 run.py / run_v2.py / run_final_v2.py、shared/cs_backtest_engine.py、factors/cross_sectional_factors.py 及 results/ 产物）
审计日期：2026-07-17

## 总体结论

README 声称的"2020-2022 训练 / 2023-2024 测试"划分在代码中并不存在：因子筛选直接在测试期上完成（in-sample selection）；基本面因子存在严重的未来数据泄漏（2026 年公告的财报被合并到 2020-2024 的所有日期）；2020-2025 扩展回测的"小盘股"分组因成交额单位错误实际是**全市场组合**，"分域建模"的关键结论（反转/低波动只在小盘有效）**不成立**。IR=0.713、IC=0.0888 是在被用于选因子的同一时段上计算的，不具备样本外含义。

## 一、确定的漏洞 / 错误

### 1. 基本面因子未来数据泄漏（最严重，影响全部脚本）

- test_factor_validity.py:51、run_v3.py:70、run_v3b_smallcap.py:54、run_final_v2.py:30 均为同一写法：
  `funda.sort_values(['ts_code','ann_date'], ascending=[True,False]).groupby('ts_code').first()` —— 取每只股票**最新一期**财报，merge 到样本内**所有**交易日。
- 实测数据：`fina_indicator_cache.parquet` 的 `ann_date` 范围为 **20230408 ~ 20260421**。即：
  - 2023-2024"测试期"的 roe/or_yoy 等因子值，实际取自最晚 2026-04-21 公告的财报（FY2025 年报），超前信息 1-2 年；
  - 2020-2022 期间 cache 中根本没有对应公告（最早 2023-04），这些日期也被填入 2025-2026 年的值，run_v3 用其训练权重 = 用未来数据训练。
- 这是 point-in-time 违规，不是简化，是确定性泄漏。

### 2. "样本外测试"实为样本内选因子

- test_factor_validity.py:100 直接加载 `20230101~20241231`（即声称的测试期），在同一时段上算 IC、做分组、决定因子方向与取舍（README 因子表即由此产生）；**没有任何 2020-2022 训练环节**。
- run_final_v2.py:104-106 注释写明"从验证结果：ret_1m(IC=0.065), ivol(IC=0.094), roe(IC=0.035) 为正"→ 据此选 `pos_factors=['ret_1m','ivol','roe']`，再在同一 2023-2024 区间回测报出 IC=0.0888（results/ic_final_v2.csv 实测 mean=0.08876，24 个月度调仓点）。这是典型的 selection bias：测试指标是在被用于挑选因子的数据上计算的。
- run_v2.py:22-77 的 `FACTOR_DIRECTIONS` 硬编码了 30+ 因子的符号，方向同样来自对同一测试期的反复观察。

### 3. run.py：树模型在测试集上重新拟合（自述泄漏）

- run.py:151-154 注释原文："测试集：使用训练好的模型预测（**简化：在测试集上重新拟合**，实际应该保存模型）"。`tree_model_combination`（cross_sectional_factors.py:546 `model.fit(X,y)` 后 550 行直接对同批数据 predict）= 训练集=测试集，完全样本内。

### 4. run_v2.py walk-forward 标签泄漏约 19 个交易日

- run_v2.py:195-233：预测窗口从第 i 日开始，训练窗口取 `all_trade_dates[i-60:i]`；训练标签 `future_ret_20d`（144 行，t 日收盘 → t+20 日收盘）对训练期末尾 19 天的样本，其标签价格落在预测窗口 i..i+19 内。即在预测日 i 做预测时，模型已用"未来 19 天价格"训练过。正确做法需把训练集标签截断到 i-20 之前。

### 5. "小盘股<5000万"是单位错误，分域结论不成立

- run_v3b_smallcap.py:175 `filter_amount_max=5e7` 过滤的是 **amount（成交额）**，不是市值；且 amount 单位为**千元**（实测 20240102：中位数 71,256 千元≈7125 万元，最大 5.44e6 千元≈54.4 亿元）。
- 5e7 千元 = **500 亿元日成交额**，实测当日 5328 只股票**全部**满足 `amount < 5e7`（过滤形同虚设）。因此：
  - results/monthly_small_2020_2025.csv（nav=1.7063）与 monthly_all（nav=1.7503）的差异**仅来自 top_n=30 vs 50**，与市值/小盘无关；
  - 中盘（5e7~5e8）、大盘（>5e8）过滤后为空，results/ 下**不存在** monthly_mid/monthly_large 文件（已核实），print_metrics 会输出"无数据"；
  - README 却称"中盘股和大盘股因子 IC 为负"——该说法**没有本次运行的证据支撑**；"小盘股(<5000万)年化 9.31%"实为全市场 30 只组合。
- run_v3.py:83-90 `assign_domain` 用同样的 bins 切 amount，全部股票落入"小盘"，中盘/大盘权重被置零（calc_weights:119-121），"分域建模"退化为单域。config.py:84 的 `cap_bins`（亿元市值口径）与实际代码（成交额口径）完全不一致。
- 回答任务设问：A 股真实市值<5000 万元的股票基本不存在（退市整理期除外）；若真按此阈值选，宇宙为空。代码实际选出的是"全市场"，并非微盘/壳股组合——但这也意味着 README 的小盘叙事是虚构的。

### 6. run_v3 训练/测试混合报告

- run_v3.py:4 自述"用 2020-2024 数据训练权重，2025 作为测试期"，但 334/337 行回测传入的是**全部 dates（2020-2025）**，报告"回测结果 2020-2025"中 60/72 个月是权重训练期内（in-sample），仅 2025 年 12 个月样本外，且未单独披露。
- calc_weights（112-136）与 backtest_global（215 行 `train = df[df['trade_date'] < '20250101']`）用的是第 1 条所述泄漏的基本面因子。
- 另：calc_ic（104-109）把多日期面板**池化**后算一个 Spearman 相关，而非逐日 IC 的均值，时序与截面混在一起，口径错误。

### 7. 全样本去极值/中性化统计量泄漏

- run_v3.py:98、run_v3b_smallcap.py:61、run_final_v2.py:77：`q01,q99 = df[c].quantile(...)` 在**全期池化样本**上计算（run_v3 为 2020-2025 全样本），再 clip；截面 z-score 本身按日做（无泄漏），但缩尾阈值含未来分布信息（轻度泄漏）。
- run.py/run_v2 走 FactorCombiner.preprocess_factors（cross_sectional_factors.py:461-491）：winsorize_series(125-129)、neutralize_industry(141-147)、neutralize_market_cap(150-159) 全部在**传入的整个面板**上操作，未按 trade_date 分组；市值中性化回归（157 行 linregress）用全期数据估斜率，再应用到期内每一天——README 声称的"行业/市值中性化"既有时序泄漏，口径也非逐日截面。且 `log_mv = log(amount+1)`（run_v2.py:141、run.py:58）用成交额代理市值做"市值中性化"，变量本身就是错的。

### 8. results/ 中存在无来源且数值荒谬的产物

- nav_gbdt.csv 与 nav_linear_v2.csv **逐字节相同**（已验证 `equals()==True`），最终 nav=835,297（两年 83 万倍），明显是某次 bug 运行的残留；现有所有脚本均不写这两个文件（grep 无匹配），属于无来源孤儿产物。"GBDT vs 线性"的对比证据因此无效。
- 没有任何脚本真正实现 README 所说的"XGBoost 组合"用于最终报告：run_v3 名为"GBDT 组合"实为 IC 加权线性；run_v2 的 XGBoost 有第 4 条泄漏；run.py 有第 3 条泄漏。

### 9. 回测引擎层面的口径问题（shared/cs_backtest_engine.py）

- 223 行：每月固定扣 0.003，与实际换手率无关，"单边 0.3%"口径粗糙。
- 持有期收益直接用 `future_ret_20d`（固定 20 个交易日），但持有期是"到下一调仓日"（15~23 个交易日不等），两者不匹配；且按调仓日**收盘价成交**，信号与成交同点（无次日开盘执行），轻度乐观。run.py:99-102 曾计算 `future_ret_20d_open`（次日开盘买入），但后续脚本均弃用。
- 226-246 行：日频净值是持有期收益的**线性插值**，日胜率、日频夏普（README 的"日胜率 45.99%、夏普 -0.148"）建立在人造日序列上，无统计意义。
- 95 行注释称"剔除 ST、停牌、涨停由数据预处理完成"，但三个脚本均无此处理；反转因子偏好大跌股，不过滤跌停/停牌会选中实际无法成交的标的。

### 10. 其他事实性错误

- "ivol"名为特质波动率，代码（test_factor_validity.py:39、run_v3.py:49）实为**总波动率**（20 日日收益 std），无市场模型残差处理；README"残差标准差"的表述与实现不符。
- test_factor_validity.py:85-90 按**日频**计算 IC，标签为未来 20 日收益，相邻 IC 自相关约 20，README 单因子 IR（0.48/0.42）被约 sqrt(20)≈4.5 倍夸大（应除以重叠调整或改用月度非重叠 IC）。
- README:100/146 声称组合权重为 ivol40%+ret_1m35%+roe15%+or_yoy5%+netprofit_yoy5%，但 run_final_v2.py:106-107 实际是三因子**等权**（`price_df[pos_factors].mean(axis=1)`），or_yoy/netprofit_yoy 并未入组。报告口径与代码不一致。

## 二、存疑、需要验证的点

1. **幸存者偏差**：data_day1 按日 parquet 存储，20240102 有 5328 只股票。需核实历史日期是否包含已退市股票（若只含当前在市股票池，2020-2021 回测段有幸存者偏差）。
2. **复权问题**：因子用 close/pre_close 计算收益，需确认 close 是否为后复权价；若未复权，送转/分红会污染 ret_1m、ivol 与 future_ret_20d。
3. **run_v3 的 IC 报告**：ic_global_2020_2025.csv 的 IC 序列同样覆盖训练期，需切分 2025 段单独验证；当前无法从产物中区分样本内外。
4. **月度成本假设**：月换手若接近 100%，单边 0.3% 低估（应双边 0.6%+）；若换手低则高估。需用 trades 记录核实真实换手。
5. **2025 年数据完整性**：load_data('20200101','20251231')，月线最后一条为 20251201。需确认 2025 年 12 月之后数据与 future_ret_20d 截尾处理（最后 20 天标签为 NaN 会被 dropna，可能静默丢弃最近月份）。
6. 多版本脚本（run/run_quick_test/run_v2/run_v3/run_v3b/run_final/run_final_v2 共 7 个）均于 2025-07-14 晚 22:23-23:10 约 1 小时内密集产出（results/ 文件时间戳），最终只报告了叙事最顺的版本——存在 p-hacking/选择性报告的模式特征，建议用注册表（STUDIES_REGISTRY.md）核对是否有未报告的失败版本。

## 三、改进建议（本任务范围内，可操作）

1. **修复基本面时点对齐（最高优先级）**：改为 merge_asof 风格——对每个交易日 t，只取 `ann_date <= t - 1`（或 t 减去安全滞后期）的最新财报；并补齐 2020-2022 的财报缓存（当前 ann_date 最早 2023-04，2020-2022 段的基本面因子应视为不可用并从该段剔除）。
2. **建立真正的样本外纪律**：把因子筛选/方向/权重确定全部锁在 2020-2022（或滚动扩展窗口内），2023-2024 只许运行一次；test_factor_validity.py 增加 `FIT_END='20221231'` 参数，选因子逻辑只看训练段输出。
3. **修正分域变量与单位**：接入真实市值字段（daily_basic 的 total_mv/circ_mv），按调仓日**当日已知**市值分档；在此之前删除 README 中所有"小盘股<5000 万"结论，并将 run_v3b 的"小盘"结果如实改标为"全市场 top30"。
4. **修复 walk-forward 与预处理泄漏**：run_v2 训练集标签截断（训练样本末日期 ≤ 预测起点-20 个交易日）；winsorize/中性化/标准化全部改为 `groupby('trade_date')` 逐日截面操作，中性化回归逐日估计。
5. **清理产物与口径**：删除或归档 nav_gbdt.csv/nav_linear_v2.csv 等孤儿文件；回测改用次日开盘价成交 + 按实际换手率双边计费；IC/IR 统一用月度非重叠标签，或日频 IC 做 Newey-West/重叠调整；README 的组合权重、夏普、日胜率按代码实际口径重算或删除。
